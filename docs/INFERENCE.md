# Инференс: предсказание ловушек на новых CPS-гридах

Прогон обученной U-Net++ по новым структурным картам и получение **маски ловушек**
в виде CPS-грида, который идеально накладывается на исходную карту. См. реализацию:
`inference/predict.py` (`run_inference`), точка входа `run_inference.py`.

## Запуск

```bash
python run_inference.py
```

В `run_inference.py` задаются `CHECKPOINT_PATH` и `INPUT_CPS_DIR` — папка с входными
гридами. Параметры качества/постобработки — в `settings.py` (группа «Инференс»).

## Входные данные

Папка с CPS-гридами в **той же номенклатуре, что при обучении** (`docs/DATA_FORMAT.md`):

| Файл | Назначение | Обязательно |
|------|------------|-------------|
| `x_structuralNOisoline_<horizon>` | структурная карта глубин (референс геометрии) | да |
| `x_faults_<horizon>` | маска разломов | нет — канал генерируется нулями |
| `y_traps_<horizon>` | маска ловушек (GT) | нет — если есть, считаются метрики |

Входная папка **не модифицируется**: нормализация имён (`clean_cps_filenames`) идёт над
копией во временной папке. `horizon_prefixes=[]` обрабатывает все горизонты; можно
ограничить списком префиксов (например `["D_70"]`).

## Что происходит внутри

```
CPS-гриды ──copy→ temp ──clean→ find_cps_files (ВСЕ горизонты)
   │
   │  на каждый горизонт:
   │    read_cps_grid(structural) → meta + valid_mask (граница карты)
   │    save_large_images → rgb/depth/isolines/faults/traps в геометрии карты
   ▼
tile_for_inference → тайлы 640×448 с полным покрытием карты + размещения
   │  (пропускаются только окна целиком вне карты; всегда есть y_traps-тайл)
   ▼
GeologyTrapsDataset(augment=False) → та же предобработка, что при обучении
   ▼
model → sigmoid (+ опц. flip-TTA) → stitch_predictions (усреднение перекрытий)
   ▼
postprocess: порог → граница карты → [морфология] → бинарная маска
   ▼
write_cps_grid (та же геометрия, Fortran-порядок) → CPS-артефакт
```

Один проход модели на горизонт: тайлы прогоняются один раз, склеенная карта
используется и для визуализации, и для метрик.

## Склейка тайлов (ключевая часть)

Обучение идёт на тайлах 640×448; инференс должен вернуть полноразмерную маску. Карта
режется тем же детерминированным layout окон, что при подготовке данных
(`utils/cps_utils.split_into_tiles`), — для каждого окна запоминается его положение.
После прогона модели тайлы **склеиваются обратно**: перекрытия усредняются, что
сглаживает швы на границах окон. Покрытие карты гарантированно без дыр (окно с хотя бы
одним пикселем карты никогда не пропускается). См. `inference/tiling.py` и проверочный
скрипт `data_validation/validate_tiling.py`.

## Выходные артефакты (папка прогона = дата+время старта)

`data/inference/{timestamp}/` (в `.gitignore`):
- `<horizon>.cps` — **маска ловушек** в формате CPS-3: `1.0` — ловушка, `0.0` — не
  ловушка (на карте), null (`0.1E+31`) — вне карты. Геометрия (nx, ny, bbox, null)
  совпадает со структурной картой → идеальное наложение.
- `<horizon>_prob.cps` (если `settings.INFERENCE_SAVE_PROBABILITY=True`) — непрерывные
  вероятности `[0, 1]`, null вне карты. Удобно для подбора порога в downstream.

`logs/inference/{timestamp}/`:
- `<horizon>.png` — визуализация на полную карту (RGB+изолинии, глубина, предсказание,
  наложение, при наличии GT — GT и карта ошибок).
- `inference_results.json` — параметры прогона, per-horizon метрики и макро-среднее.

## Метрики

Считаются **по полной карте** (не по тайлам): склеенная предсказанная маска vs GT в
границах карты (`valid_mask = ~isnan(structural)`). Каждый пиксель карты учитывается
один раз — это «взгляд геолога», а не per-tile микро-агрегация (`evaluate_on_raw_cps`).
Поэтому числа здесь и в `evaluate_model.py` могут различаться — это ожидаемо. Метрики
доступны только для горизонтов с GT-ловушками; для остальных в JSON `metrics: null`.

## Настройки качества (`settings.py`)

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `INFERENCE_THRESHOLD` | 0.5 | порог бинаризации вероятностей |
| `INFERENCE_MIN_TRAP_AREA_PX` | 0 | убрать связные ловушки < площади (0 = выкл.) |
| `INFERENCE_FILL_HOLES` | False | заполнить дыры внутри ловушек |
| `INFERENCE_TTA` | False | test-time augmentation горизонтальным отражением |
| `INFERENCE_SAVE_PROBABILITY` | False | дополнительно сохранить CPS вероятностей |

По умолчанию выключено всё, кроме порога — первый артефакт это «сырой» вывод модели.
Рекомендуется поэкспериментировать: `INFERENCE_FILL_HOLES=True` + небольшой
`INFERENCE_MIN_TRAP_AREA_PX` убирают шум, который в downstream мог бы породить
спорадические мелкие ловушки.

## Использование в downstream-проекте

CPS-грид `<horizon>.cps` — это маска ловушек в той же геометрии, что и структурная
карта. Дальше: наложение на структурную карту глубин, выделение изолиний по границам
ловушек и расчёт ресурсов нефти и газа. Значения: 1 = ловушка, 0 = не ловушка, null =
вне карты.

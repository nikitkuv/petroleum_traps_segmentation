# Теория конвертации CPS-гридов в изображения

Документ описывает **идею и математику** преобразования, а не API функций.
Реализация — `data/convert_cps_to_tiles.py` и `utils/cps_utils.py`.

---

## 1. Что такое CPS-грид

CPS (CPS-3 / Petrel-style ASCII grid) — это текстовый файл, описывающий
регулярную сетку значений геологического параметра (глубины, амплитуды и т.д.)
в мировых координатах. Каждый грид несёт три блока информации:

1. **Геометрия сетки** — размер и охват в метрах:
   - `nx`, `ny` — число узлов по X и Y;
   - `xmin, xmax, ymin, ymax` — мировой bounding box (координаты углов).
2. **Значения параметра** — вещественные числа глубины/амплитуды в каждом узле.
3. **Null-значение** (`-999.0` по умолчанию) — маркер «нет данных»
   (ячейка за пределами карты / не рассчитана).

Из заголовка читаются строки-маркеры:
`FSASCI` → null-значение, `FSNROW ny nx` → размер, `FSLIMI xmin xmax ymin ymax` → bbox,
строка `->` → начало блока чисел.

### Node-centered геометрия

CPS-грид **node-centered**: узлы лежат на самих границах bbox, а не в центрах ячеек.
Поэтому мировые координаты узла вычисляются как

```
col j  ->  X = xmin + j * (xmax - xmin) / (nx - 1)        j = 0..nx-1
row i  ->  Y = ymax - i * (ymax - ymin) / (ny - 1)        i = 0..ny-1
```

Здесь **row 0 = верх карты = ymax** (Y убывает сверху вниз, как в изображении).
Это ключевое свойство: именно поэтому данные reshape'ятся в `order='F'`
(Fortran-order — по столбцам) и именно по этой формуле строится пересчёт
координат между гридами.

## 2. Какие гриды используются и зачем каждый

Для одного горизонта (структурной поверхности) имеются до трёх CPS-гридов:

| Грид | Что хранит | Роль в задаче |
|------|------------|---------------|
| **structural** | карта глубин (непрерывное поле) | главный источник входных признаков; задаёт референсную пиксельную сетку |
| **faults** | маска разломов | бинарный канал + маска «недостоверных» зон |
| **traps** | маска ловушек | **целевая маска** (таргет сегментации) |

Гриды faults/traps могут иметь **другое разрешение** (другой размер ячейки),
поэтому их нельзя использовать «как есть» — их нужно сначала посадить на ту же
сетку, что и structural.

---

## 3. Выравнивание гридов на общую сетку (референс)

Структурная карта объявляется **референсом**: её пиксельная сетка становится
канонической для всего горизонта. Faults и traps переносятся на неё по мировым
координатам, чтобы все карты легли пиксель-в-пиксель.

Алгоритм пересчёта (`resample_grid_to_reference`):

1. Для каждого узла референса `(i_r, j_r)` вычисляем его мировые координаты
   `(X, Y)` по формуле node-centered (см. выше).
2. Те же мировые координаты переводим в **дробные индексы** исходного грида
   `(fi, fj)` — обращая формулу.
3. Через `cv2.remap` с интерполяцией `INTER_NEAREST` берём ближайшее значение
   исходного грида. Ближайший сосед выбран намеренно: faults/traps — бинарные
   маски, любая интерполяция (билинейная) размыла бы их и породила
   промежуточные значения.
4. Отдельно ремапится **маска валидности** исходного грида. Точки, попавшие
   вне охвата исходника, помечаются `NaN` — это сохраняет корректную границу
   «нет данных» после пересчёта.

Результат: faults и traps получают ту же форму `(ny, nx)`, что и structural,
с единым bbox и размером ячейки.

---

## 4. Как значения глубины превращаются в пиксели

Из одного поля глубин structural строятся **три разных представления** — каждое
несёт свой тип информации для модели.

### 4.1. RGB (structuralNOisoline) — визуальный канал

1. **Min-max нормализация** значений в `[0, 1]`:
   `v_norm = (v - vmin) / (vmax - vmin)`.
2. Применяется цветовая карта **purple_jet** (индиго → синий → голубой →
   зелёный → жёлтый → оранжевый → красный) — низкие глубины «холодные»,
   высокие «тёплые».
3. Значения переводятся в `uint8 [0, 255]`, NaN (вне карты) → чёрный `(0,0,0)`.

Назначение: дать модели те же визуальные подсказки, что видит геолог
(цветовые градиенты рельефа). Это семантически избыточно с depth, но несёт
нелинейное, хорошо разделяющее отображение.

### 4.2. Depth (structuralBlackWhite) — числовой канал

1. Та же min-max нормализация в `[0, 1]`.
2. Сохраняется как **`float32` массив `.npy`** — без перевода в 8-бит, без
   потери точности (PNG квантует до 256 уровней).

Назначение: линейное, метрически осмысленное представление глубины — модель
видит настоящие относительные перепады высот, а не цветовой код.

### 4.3. Isolines — структурные линии

1. По диапазону `[vmin, vmax]` строится набор уровней с шагом 5 м
   (от `floor(vmin/5)*5` до `ceil(vmax/5)*5`).
2. Для каждого уровня строится бинарная маска «поверхность ≥ level».
3. Через `cv2.findContours` извлекаются контуры и рисуются толщиной 1 пиксель.

Назначение: изолинии — это дискретное кодирование градиента рельефа.
Ловушки (замкнутые контуры) геологически часто формируются на структурных
замыканиях, поэтому плотность и форма изолиний — сильный признак.

---

## 5. Как faults и traps становятся бинарными масками

CPS-гриды faults и traps — это по сути поля 0/1 (или null вне карты).
Конвертация через `cps_to_binary_mask`:

1. Min-max нормализация в `[0, 1]` (чтобы шкала стала воспринимаемой).
2. **Порог бинаризации** `BINARY_THRESHOLD = 128` (из 255): всё, что выше
   порога → 1, ниже → 0.
3. Вне карты (NaN) принудительно 0.

Затем маска умножается на 255 и сохраняется как `uint8` PNG (255 = объект,
0 = фон).

> Замечание: faults и traps переносятся на сетку structural **до** бинаризации
> (раздел 3), поэтому порог применяется уже к выровненному гриду.

---

## 6. Вырезание разломов из признаковых карт

Разломы — это зоны тектонического смещения, где структурная карта **не
достоверна**: между бортами разлома значения интерполируются через разрыв и
физически бессмысленны. Чтобы модель не училась на этих артефактах:

- пиксели маски faults обнуляются в **RGB**, **depth** и **isolines**
  (становятся чёрными/нулевыми).

Позже в `dataset.py` на основе этого же нуля строится канал `map_mask`:
`0` ставится и на «вне карты», и на «разлом» — masked-лосс игнорирует обе зоны.

## 7. Нарезка на тайлы

Полноразмерные карты слишком велики для обучения целиком, поэтому они режутся
на тайлы фиксированного размера `640 (H) × 448 (W)` с **перекрытием 25%**
(шаг = 0.75 × размер тайла).

Теория тайлинга:

1. **Сетка окон со сдвигом.** Окна размещаются с шагом `stride`, поэтому
   соседние тайлы перекрываются на 25%. Перекрытие нужно, чтобы объект
   (ловушка), рассечённый границей окна, целиком попадал хотя бы в один тайл.
2. **Прижим краёв.** Последний по строке/столбцу тайл сдвигается назад, чтобы
   покрыть правый/нижний край без потери полосы пикселей.
3. **Паддинг.** Если тайл на краю меньше `640×448`, он дополняется нулевой
   рамкой (`pad_image`) до точного размера — модель требует фиксированный
   вход.
4. **Фильтрация пустых тайлов.** Тайл отбрасывается, если в нём меньше
   `MIN_NUM_PIXS_OF_TRAPS_IN_TILES = 100` пикселей ловушек. Пустые тайлы
   не несут сигнала для сегментации и только разбалансируют выборку.

Каждый тайл получает имя `{NNN}_{role}_{type}_{horizon}.{ext}`, где `NNN` —
порядковый номер тайла горизонта. Все каналы одного тайла (rgb, depth, isolines,
faults, traps) режутся из **одного и того же окна** — поэтому остаются
выровненными пиксель-в-пиксель.

## 8. Сводка потока информации

```
CPS-грид depth      ─┬─► RGB           (colormap, визуальные признаки)
                     ├─► depth.npy     (линейная глубина, float32)
                     └─► isolines      (контуры с шагом 5м)

CPS-грид faults  ─► resample ─► binary mask ─┬─► faults канал
                                            └─► обнулить в RGB/depth/iso

CPS-грид traps   ─► resample ─► binary mask ─► target (y_traps)
```

**Что берём из CPS:** геометрию (bbox + nx/ny, node-centered), поле значений
и null-маркеры. **Как используем:** structural задаёт сетку и три признаковых
представления; faults/traps пересчитываются на эту сетку и бинаризуются.
**Как конвертируем в изображение:** нормализация → colormap/порог → `uint8` PNG
(или `float32 .npy` для depth) → нарезка на выровненные тайлы с фильтром пустых.

# Формат имен файлов для проекта Geology Traps

## Структура именования

Формат: `{number}_{x|y}_{type}_{name}.png`

### Компоненты:
- **number**: Номер карты (например, `001`, `002`, `003`)
- **role**: Роль файла - `x` (входные данные) или `y` (целевая маска)
- **type**: Тип данных
- **name**: Название горизонта или идентификатор карты (например, `H150`, `BZ24`, `Field_A`)

### Типы файлов

#### Входные данные (x):
| type | Описание | Канал в модели |
|------|----------|----------------|
| `structuralNOisoline` | RGB карта без изолиний и разломов | rgb (3 канала) |
| `structuralBlackWhite` | Черно-белая карта глубины (0=высокие точки, 255=низкие) | depth_norm (1 канал) |
| `faults` | Карта разломов (опционально) | faults (1 канал) |

#### Целевые данные (y):
| type | Описание | Канал в модели |
|------|----------|----------------|
| `traps` | Карта ловушек (таргет) | traps (1 канал) |

## Примеры имен файлов

### Один семпл (горизонт H150, карта 001):
```
001_x_structuralNOisoline_H150.png      # RGB карта без изолиний
001_x_structuralBlackWhite_H150.png     # Depth нормализованный
001_x_faults_H150.png                   # Разломы (опционально)
001_y_traps_H150.png                    # Ловушки (таргет)
```

### Другой номер карты того же горизонта - ДРУГОЙ семпл:
```
002_x_structuralNOisoline_H150.png
002_x_structuralBlackWhite_H150.png
002_x_faults_H150.png
002_y_traps_H150.png
```

### Другой горизонт - ДРУГОЙ семпл:
```
001_x_structuralNOisoline_H100.png
001_x_structuralBlackWhite_H100.png
001_x_faults_H100.png
001_y_traps_H100.png
```

## Группировка данных

### Семпл
Семпл определяется комбинацией `{number}_{name}`:
- `001_H150` = все файлы с number=001 и name=H150
- `002_H150` = отдельный семпл (другая карта того же горизонта)
- `001_H100` = отдельный семпл (другой горизонт)

### Разделение на train/val/test
Разделение происходит по **горизонтам (name)**, чтобы:
- Все карты одного горизонта попадали в одну выборку
- Модель не видела данные из тестовых горизонтов при обучении

Пример:
- Если `H150` попал в test, то ВСЕ карты (`001_H150`, `002_H150`, ...) будут в test
- Если `H100` попал в train, то ВСЕ карты (`001_H100`, `002_H100`, ...) будут в train

## Конфигурация режимов данных

### Режим "без разломов" (use_faults=False)
Для обучения без учета разломов используются 4 входных канала + target:
- `001_x_structuralNOisoline_H150.png` → rgb (3 канала)
- `001_x_structuralBlackWhite_H150.png` → depth_norm (1 канал)
- `001_y_traps_H150.png` → traps (target)

**Итого входных каналов**: 4 (RGB + depth)
**Маски**: map_mask (для игнорирования фона за пределами карты)

### Режим "с разломами" (use_faults=True)
Для обучения с учетом разломов используются 5 входных каналов + target:
- `001_x_structuralNOisoline_H150.png` → rgb (3 канала)
- `001_x_structuralBlackWhite_H150.png` → depth_norm (1 канал)
- `001_x_faults_H150.png` → faults (1 канал)
- `001_y_traps_H150.png` → traps (target)

**Итого входных каналов**: 5 (RGB + depth + faults)
**Маски**: map_mask + depth_mask (depth_mask = map_mask × (1 - faults))

## Вспомогательные маски

### map_mask
- **Назначение**: Игнорировать фон за пределами карты
- **Расчет**: Создается автоматически из RGB изображения (пиксели < 250 считаются картой)
- **Значения**: 1 = область карты, 0 = фон/паддинг
- **Используется**: Всегда в обоих режимах

### depth_mask
- **Назначение**: Игнорировать области под разломами при обучении
- **Расчет**: depth_mask = map_mask × (1 - fault_mask)
- **Значения**: 1 = учитываем при обучении, 0 = игнорируем
- **Используется**: Только в режиме с разломами (use_faults=True)

## Парсинг имен файлов

Функция `parse_filename()` в `data/dataloaders.py`:
```python
parse_filename("001_x_structuralNOisoline_H150.png")
# Returns: {
#     'number': '001',
#     'role': 'x',
#     'type': 'structuralNOisoline',
#     'name': 'H150'
# }
```

Функция `_parse_files()` в `dataset.py` группирует файлы по семплам.

## Требования к данным

### Размеры изображений
- Исходный размер: 505 (ширина) × 1218 (высота)
- После паддинга: 512 × 1248
- Паддинг добавляется автоматически с использованием `cv2.BORDER_CONSTANT`

### Форматы
- Формат файлов: PNG
- RGB изображения: 3 канала (0-255)
- Grayscale изображения: 1 канал (0-255)
- Бинарные маски: 1 канал (0 или 1, float32)

### Цветовые конвенции
- **structuralNOisoline**: RGB палитра от синего (низкие) до красного (высокие)
- **structuralBlackWhite**: 0=наивысшие точки, 255=низшие точки
- **faults**: 0=разломы (черный), 255=не разломы (белый)
- **traps**: 0=ловушки (черный), 255=не ловушки (белый)

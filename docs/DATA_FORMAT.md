# Формат данных проекта Geology Traps Segmentation

## Обзор источников данных

Проект использует один источник данных:

1. **`cps_tiles`** - PNG файлы, сконвертированные из CPS гридов - тайлы определенного размера

---

## Источник данных: cps_tiles

### Исходные данные

Изначально имеются CPS гриды:
- **CPS грид карты глубин** — структурная карта глубин
- **CPS грид карты ловушек** — бинарная маска (1 = ловушка, 0 = не ловушка)
- **CPS грид разломов** (опционально) — бинарная маска разломов

### Пайплайн обработки данных (CPS → PNG тайлы)

Пайплайн загрузки и обработки входных данных из CPS гридов:

1. **Загрузка CPS гридов** (больших карт глубин, ловушек и разломов)
2. **Трансформация CPS гридов в изображения**:
   - Карты глубин конвертируются в:
     - `rgb` (PNG) — RGB карта без изолиний (colormap purple_jet)
     - `isolines` (PNG) — бинарная маска с белыми изолиниями
     - `faults` (PNG) — бинарная маска разломов
     - `traps` (PNG) — бинарная маска ловушек (таргет)
   - Карты глубин конвертируются в:
     - `depth_norm` (.npy) — нормализованная карта глубин в черно-белой палитре (сохраняется как float32 массив NumPy)
3. **Ресайз карт разломов**: CPS гриды разломов часто имеют большее разрешение (больше ячеек, меньший размер ячейки), чем структурные карты и карты ловушек, поэтому они ресайзятся до размера структурных карт с использованием интерполяции ближайшего соседа (`cv2.INTER_NEAREST`)
4. **Вырезание невалидных областей**: На картах `rgb`, `depth_norm` и `isolines` значения за пределами карты и в местах разломов заполняются 0 (черный цвет)
5. **Нарезка на тайлы**: Большие изображения нарезаются на тайлы размером 640×448 с overlap и сохраняются в PNG (для depth_norm — в .npy)
6. **Загрузка в dataset**: PNG/.npy тайлы загружаются, карты `rgb` и `depth_norm` нормируются в диапазон [0, 1]
7. **Генерация map_mask**: В dataset автоматически создается маска `map_mask`, где:
   - 1 = валидная область карты
   - 0 = невалидная область (за пределами карты ИЛИ разломы)
   - `map_mask` добавляется как отдельный входной канал модели

### Структура именования файлов

Формат: `{number}_{x|y}_{type}_{name}.png`

### Компоненты:
- **number**: Номер карты (например, `001`, `002`, `003`)
- **role**: Роль файла - `x` (входные данные) или `y` (целевая маска)
- **type**: Тип данных (канал)
- **name**: Название горизонта или идентификатор карты (например, `H150`, `BZ24`, `Ach3-2-1_toptop1`)

### Типы файлов для cps_tiles

#### Входные данные (X):

| Канал | type | Описание | Формат | Нормализация |
|-------|------|----------|--------|--------------|
| 1. rgb | `structuralNOisoline` | RGB карта без изолиний и разломов (purple_jet colormap) | uint8 PNG / float32 | [0, 1] |
| 2. depth_norm | `structuralBlackWhite` | Карта глубин в черно-белой палитре | float32 (.npy) | [0, 1] (0 - низко, 1 - высоко) |
| 3. isolines | `isolines` | Бинарная маска с белыми изолиниями на черном фоне | uint8 PNG | бинарная |
| 4. faults | `faults` | Бинарная маска разломов (опционально) | uint8 PNG | бинарная (1 - разломы, 0 - фон) |
| 5. map_mask | (генерируется) | Бинарная маска валидной области карты | float32 | бинарная (1 - валидная область, 0 - за пределами карты и разломы) |

**Важно о map_mask:**
- Создается автоматически из RGB изображения в `dataset.py`
- Включает в себя как области за пределами карты, так и области разломов
- Оба типа невалидных областей заполняются 0 (черный цвет)
- Добавляется как дополнительный входной канал для обучения модели

**Итого входных каналов в модели:**
- Без разломов (`USE_FAULTS=False`): **6 каналов** (RGB(3) + Depth(1) + Isolines(1) + MapMask(1))
- С разломами (`USE_FAULTS=True`): **7 каналов** (RGB(3) + Depth(1) + Isolines(1) + Faults(1) + MapMask(1))

#### Целевые данные (Y):

| Канал | type | Описание | Формат |
|-------|------|----------|--------|--------|
| traps | `traps` | Бинарная маска ловушек (таргет) | uint8 PNG | бинарная (1 - ловушки, 0 - фон) |

## Группировка данных

### Семпл
Семпл определяется комбинацией `{number}_{name}`:
- `001_H150` = все файлы с number=001 и name=H150
- `002_H150` = отдельный семпл (другая карта того же горизонта)
- `001_H100` = отдельный семпл (другой горизонт)

### Разделение на train/val/test
Разделение происходит по **горизонтам (name)**, чтобы:
- Все карты одного горизонта попадали в одну выборку
- Модель не видела данные из тестовых горизонтов при обучении

Пример:
- Если `H150` попал в test, то ВСЕ карты (`001_H150`, `002_H150`, ...) будут в test
- Если `H100` попал в train, то ВСЕ карты (`001_H100`, `002_H100`, ...) будут в train

## Конфигурация режимов данных

### Режим "без разломов" (use_faults=False)

#### Для cps_tiles:
Для обучения без учета разломов используются 6 входных каналов + target:
- `001_x_structuralNOisoline_H150.png` → rgb (3 канала)
- `001_x_structuralBlackWhite_H150.npy` → depth_norm (1 канал)
- `001_x_isolines_H150.png` → isolines (1 канал)
- `001_y_traps_H150.png` → traps (target)
- map_mask генерируется автоматически из RGB (1 канал)

**Итого входных каналов**: 6 (RGB + depth + isolines + map_mask)

### Режим "с разломами" (use_faults=True)

#### Для cps_tiles:
Для обучения с учетом разломов используются 7 входных каналов + target:
- `001_x_structuralNOisoline_H150.png` → rgb (3 канала)
- `001_x_structuralBlackWhite_H150.npy` → depth_norm (1 канал)
- `001_x_isolines_H150.png` → isolines (1 канал)
- `001_x_faults_H150.png` → faults (1 канал)
- `001_y_traps_H150.png` → traps (target)
- map_mask генерируется автоматически из RGB и включает разломы (1 канал)

**Итого входных каналов**: 7 (RGB + depth + isolines + faults + map_mask)

## Вспомогательные маски

### map_mask
- **Назначение**: Игнорировать невалидные области (фон за пределами карты + разломы)
- **Расчет**: Создается автоматически в `dataset.py` из RGB изображения:
  1. Базовая маска карты: пиксели > 10 считаются областью карты (1), остальное - фон (0)
  2. При использовании разломов: области разломов добавляются в маску как невалидные (0)
- **Значения**:
  - 1 = валидная область карты
  - 0 = невалидная область (за пределами карты ИЛИ разломы)
- **Используется**: Всегда в обоих режимах как дополнительный входной канал модели
- **Важно**: map_mask включается в число входных каналов модели (X), а не используется только для loss

## Требования к данным

### Размеры изображений

#### Для cps_tiles:
- Исходный размер CPS гридов зависит от источника
- После тайлинга: 448 (ширина) × 640 (высота)
- Паддинг добавляется автоматически с использованием `cv2.BORDER_CONSTANT`

### Форматы
- Формат файлов: PNG
- RGB изображения: 3 канала (0-255), uint8
- Grayscale изображения: 1 канал (0-255), uint8
- Бинарные маски: 1 канал (0 или 1, float32 после нормализации)

### Цветовые конвенции

#### Для cps_tiles:
- **structuralNOisoline**: RGB палитра purple_jet от индиго/фиолетового (низкие) до красного (высокие)
- **structuralBlackWhite**: 0=наивысшие точки, 255=низшие точки (в нормализованном виде: 0=низко, 1=высоко)
- **isolines**: 0=фон (черный), 255=изолинии (белые линии)
- **faults**: 1=разломы (белый), 0=не разломы (черный)
- **traps**: 1=ловушки (белый), 0=не ловушки (черный)
- **map_mask**: 1=валидная область карты (белый), 0=невалидная область - за пределами карты или разломы (черный)

**Важно**:
- В режиме с разломами области разломов на картах rgb, depth_norm и isolines вырезаются (становятся черными/0)
- map_mask создается в dataset.py и включает как области за пределами карты, так и области разломов (оба типа заполняются 0)
- map_mask добавляется как дополнительный входной канал для обучения модели

### Конвертация из CPS в PNG/.npy

Конвертация выполняется скриптом `data/convert_cps_to_tiles.py`:

1. **Чтение CPS грида**: Парсинг заголовков FSASCI, FSNROW, FSLIMI
2. **Генерация RGB**: Применение colormap purple_jet к нормализованным значениям глубин
3. **Генерация grayscale (depth_norm)**: Нормализация к [0, 1] с сохранением как float32 массив NumPy (.npy файл)
4. **Генерация изолиний**: cv2.findContours с шагом 5м
5. **Ресайз разломов**: Если CPS грид разломов имеет другое разрешение, он ресайзится до размера структурной карты с использованием `cv2.INTER_NEAREST`
6. **Вырезание разломов**: Области разломов на картах rgb, depth_norm и isolines становятся черными (0)
7. **Сохранение больших изображений**: Полные карты сохраняются в `data/images_cps_full/` (PNG для rgb/isolines/faults/traps, .npy для depth_norm)
8. **Тайлинг**: Разбиение больших изображений на тайлы размером 448×640 с overlap 25%

### Минимальные требования к данным

#### Для cps_tiles:
- Наличие CPS файлов с структурными картами (`x_structuralNOisoline_*.cps`)
- Наличие CPS файлов с картами ловушек (`y_traps_*.cps`) - опционально для генерации таргетов
- Наличие CPS файлов с разломами (`x_faults_*.cps`) - опционально для режима с разломами
- CPS файлы должны содержать корректные заголовки FSNROW, FSLIMI

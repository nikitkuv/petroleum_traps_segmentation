# Сравнение режимов предсказания: evaluate (пертайл) vs inference (склейка)

Скрипт `compare_inference.py` прогоняет одни и те же карты через две пайплайны и
сравнивает метрики, чтобы ответить на вопрос: **ухудшает ли склейка тайлов в единую
карту качество предсказаний** относительно опорного пертайлового режима
(`evaluate_model.py`).

## Два сравниваемых режима

| | **evaluate** (пертайл) | **inference** (склейка) |
|---|---|---|
| Код | `evaluation/evaluate_on_raw_cps` | `inference.predict.run_inference` |
| Модель по тайлам | да | да |
| Склейка тайлов в карту | **нет** — метрики по тайлам | **да** — `stitch_predictions` (усреднение перекрытий) |
| Метрики | пертайловые + микро-агрегация по горизонту | по полной карте (каждый пиксель 1 раз) |
| Визуализация | пертайловая (`{NN}_{horizon}_results.png`) | на полную карту (`{horizon}.png`) |
| CPS-артефакт | нет | да (`{horizon}.cps`) |

Обе пайплайн используют **одну модель, один порог и одни тайлы** — сравнение честное.

## Что изолирует сравнение

Чтобы разница в метриках отражала **только** эффект склейки, а не побочные факторы:

- **Одинаковый вход.** Выбранные карты копируются во временную папку `_cmp_in/`; обе
  пайплайн читают её. Оригиналы в `data/cps/` не трогаются.
- **`min_traps_pixels=0` для evaluate** → обрабатываются ВСЕ тайлы (как у инференса),
  иначе evaluate пропускал бы пустые тайлы и покрытие бы не совпало.
- **Постобработка инференса выключена** (`min_trap_area_px=0`, `fill_holes=False`,
  `tta=False`) → сравнивается «чистая» склейка, без морфологии/TTA.

После этого единственные содержательные отличия:
1. **Усреднение перекрытий** — в зонах, где 2–4 тайла перекрываются, инференс берёт
   среднее вероятностей, evaluate считает каждый тайл отдельно.
2. **Метод подсчёта метрик** — evaluate микро-агрегирует тайлы (пиксель в перекрытии
   учитывается 2–4 раза); инференс считает каждый пиксель карты один раз.

Для долевых метрик (Dice/IoU) это почти нейтрально, когда перекрывающиеся тайлы
согласованно предсказывают один и тот же класс.

## Запуск

```bash
python compare_inference.py
```

В `compare_inference.py` сверху задаётся `MAPS` — список карт (имена горизонтов).
Набор по умолчанию намеренно разный по размеру: от 1 тайла до ~12, чтобы увидеть
поведение и без перекрытий, и при большом числе оверлапов.

## Артефакты (папка прогона = дата+время)

- `logs/test_inference/evaluate/{ts}/` — пертайловые визуализации + `test_metrics.json`.
- `logs/test_inference/inference/{ts}/` — визуализации на полную карту + `inference_results.json`.
- `data/inference/{ts}/` — CPS-гриды предсказаний (только у инференса).

## Как читать таблицу сравнения

Скрипт печатает таблицу: для каждой карты две строки (`eval`, `infer`) и снизу
агрегированные. Ключевые столбцы — `Dice`, `IoU` (долевые, основные), `Recall`/`Prec`,
`FP%`/`FN%` (доли ложных срабатываний/пропусков по площади карты).

**Признаки того, что склейка НЕ ухудшает качество:**
- `Dice`/`IoU` у `infer` отличаются от `eval` на ~1% или меньше;
- на картах без перекрытий (1 тайл) значения практически идентичны;
- на картах с перекрытиями (много тайлов) разница остаётся в тех же пределах, а
  `FP%`/`FN%` не растут заметно.

**На что обращать внимание:**
- Небольшой рост `FP%` у инференса — ожидаем: полная карта считает FP-пиксели по всей
  площади, включая спорные у порога в зонах перекрытия; это обычно доли процента.
- `Recall`/`Prec` могут слегка «перетекать» друг в друга из-за усреднения вероятностей
  у порога — это не деградация, а сглаживание швов.

## Ограничения

- evaluate агрегирует тайлы **по базовому горизонту** (`extract_base_horizon`: суффиксы
  вида `_toptop1`/`_bottop1` отбрасываются). Если в `MAPS` добавить две карты одного
  базового горизонта (напр. `H150_toptop1` и `H150_toptop2`), evaluate свернит их в
  одну строку, а инференс оставит раздельно — учтите это при трактовке.
- Метрики двух режимов методически различны (см. выше), поэтому это сравнение
  «качества склейки», а не побайтовое равенство. Полное совпадение не ожидается.

## Эталонный результат (чекпоинт v4, 4 карты)

| Карта | Режим | Тайлов | Dice | IoU | Recall | Prec | FP% | FN% |
|---|---|---|---|---|---|---|---|---|
| Ach3-2-1 (1 тайл) | eval / infer | 1 | 0.715 / 0.715 | 0.556 / 0.556 | 0.862 / 0.862 | 0.611 / 0.611 | 0.021 / 0.023 | 0.005 / 0.006 |
| H150 (2 тайла) | eval / infer | 2 | 0.886 / 0.877 | 0.795 / 0.780 | 0.852 / 0.842 | 0.923 / 0.914 | 0.008 / 0.009 | 0.017 / 0.019 |
| CS1 (val, 2 тайла) | eval / infer | 2 | 0.672 / 0.682 | 0.507 / 0.518 | 0.652 / 0.703 | 0.696 / 0.663 | 0.008 / 0.017 | 0.010 / 0.014 |
| **U9_10 (12 тайлов)** | eval / infer | 12 | **0.447 / 0.460** | **0.295 / 0.299** | 0.626 / 0.509 | 0.417 / 0.419 | 0.029 / 0.028 | 0.021 / 0.020 |

**Вывод: склейка не ухудшает качество.** На всех картах Dice/IoU (основные долевые
метрики сегментации) у инференса совпадают с evaluate или чуть выше — в том числе на
крупной 12-тайловой карте (0.447 → 0.460 Dice), где перекрытий больше всего.

### Важная оговорка про Recall на картах с перекрытиями

На 12-тайловой карте Recall у инференса ниже (0.626 → 0.509). **Это не потеря качества**,
а эффект методики подсчёта + консервативности усреднения у порога:

- **Площадные метрики FP%/FN% практически идентичны** (0.029/0.028 и 0.021/0.020) —
  это самый надёжный, методико-независимый показатель: реальная площадь ложных
  срабатываний и пропусков не изменилась. Если бы склейка реально теряла ловушки,
  FN% бы вырос — а он не вырос.
- evaluate считает пиксели в зонах перекрытия **несколько раз** (пертайловая
  микро-агрегация): кластеризованные GT-ловушки в перекрытиях учитываются 2–4 раза и
  завышают Recall. Инференс считает каждый пиксель один раз — это «честный» per-pixel
  Recall.
- В перекрытиях усреднение вероятностей двух тайлов чуть консервативнее у порога
  (0.6+0.3 → 0.45 < 0.5), поэтому часть спорных пикселей уходит из TP. На долевые
  метрики (Dice/IoU) и на площади ошибок это не влияет.

### Оговорка про агрегированные строки

Строка `AGGREGATED` у evaluate — **микро** по всем тайлам всех карт (карта с бóльшим
числом тайлов перевешивает), у инференса — **макро** (простое среднее по картам). Из-за
разной агрегации эти строки **напрямую не сравнимы** — сравнивать надо попарные строки
по каждой карте (там обе пайплайны относятся к одному горизонту).
